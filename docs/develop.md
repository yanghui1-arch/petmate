# Develop
该文档为开发者提供一套符合该项目风格的开发风格。主要分为主进程和渲染进程。渲染进程只负责页面渲染，主进程只负责逻辑。<br/>
请为每一个方法写上注释，否则无法通过pr<br/>

## 测试代码
### 没有添加新的功能
若开发者没有添加新的功能，再实现完自己的逻辑之后，应该`npm run test`一下测试，如果全部通过，则可以提交pr，否则应该检查自己的逻辑是否有误或测试代码是否有问题
1. 开发逻辑问题<br/>
    修改自己的逻辑，请保证可以通过所有测试用例
2. 测试代码有错误<br/>
    若是测试代码有问题，请创建一个新的分支并提出pr，在pr中请详细解释该测试代码的问题所在，并提出自己的测试代码
### 添加了新的功能
若开发者开发了新的功能，请提供对应的测试代码供代码审查以及方便日后的代码测试。
## Main
### 为渲染层提供接口
若开发者尝试为渲染层暴露一个方法，以使得渲染层可以调用此方法。请遵守如下规则。
1. 请在src/main/ipc.ts中暴露该方法
2. 请在src/preload/index.ts中的api下面定义好
3. 请在src/preload/index.d.ts中全局声明
4. 请在src/renderer/types/electron.d.ts中全局声明
### 提供默认数据
若开发者想要新增某个物品/Buff等等此类游戏内的机制或者是物品之类的东西，请遵守如下规则。
1. 请提供.json文件，并将其放入到src/main/assets目录下
2. 若src/main/store.ts中没有负责读写你这个东西的Manager，请自己实现这个Manager。若你没有同步实现这个Manager，该次PR不会被通过。
请注意，如果你只是添加一个新的物品/一个全新的Buff等此类目前已经支持的东西，仅需要在对应的json文件中添加即可，无需改动任何代码
### 提供工具方法
若开发者想为主进程提供一些工具方法，使得代码逻辑变得清晰（我们非常推荐开发者这样做），请遵守如下规则。
1. 请在src/main/modules/utils目录下实现你得代码
2. 若是跟文件有关得请在file.ts中实现
3. 若是跟数据计算/数值匹配等数学类的工具方法，请在calc.ts中实现
### 提供展示信息的方法
若开发者想为渲染层提供某种信息的数据，请遵守如下规则。
1. 将代码写在src/main/modules/show.ts，这里是所有展示信息的代码的文件
### 常数
请将常数数据定义在src/main/constant.ts文件中
### 异常
若开发者想定义某个错误/异常，请在src/main/error.ts文件中定义，在定义之前请先查看是否有已经写好的异常/错误可直接调用，请勿重复实现类似的异常代码
## Renderer
### 颜色
开发者在使用颜色的时候，请保持其颜色和主题颜色一致，尽量只使用src/renderer/assets/style/color.css 如无特殊必要请不要使用其他的颜色

### 鼠标
1. 开发者在定义鼠标的css样式的时候，请不要使用`cursor: pointer`，petmate项目有自带的全局鼠标样式，开发者可以在src/renderer/assets/global.scss中看到**按钮等类型和`class="clickable"`**的组件有自带的鼠标样式，因此，请开发者不要定义鼠标样式。
2. 若开发者想要更改鼠标样式，请直接改动src/renderer/assets/cursor中的两张图片，保持命名一致之后，提交pr
### 与主进程的通信
在electron项目中，渲染层想与主进程通信，需要通过preload，在这个过程中，需要在渲染层的types/electron.d.ts中声明方法，否则会报错
