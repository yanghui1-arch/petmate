## 三、实施方案比较

| 方案 | 设计 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- |
| A：页面内直接修改 | 在 `Farm.vue` 的现有变量和事件处理函数中加入工具标记、图片和右键操作 | 文件改动少，初期修改快 | 多个状态变量容易产生冲突；播种、布置、浮层、取消的事件顺序较难核查 | 只增加一项简单操作、后续不扩展工具 |
| B：Vue/CSS 统一工具状态＋共用图片组件 | 保留 Vue/CSS 场景，使用轻量 Hook 管理当前工具、悬停及取消；共用图片组件展示作物阶段和装饰；页面继续负责业务提交 | 状态互斥清楚，图片可复用，方便验证；沿用现有服务与素材 | 需新增少量模块，并梳理旧事件与断言 | 当前五种场景状态、多个物品面板及明确取消规则 |
| C：Vue＋Phaser 场景（已选择） | Phaser 场景负责对象、动画、指针和命中检测，Vue 保留图文面板 | 便于后续大量对象、特效与动画 | 改动范围大，须重新验证缩放、事件及场景绘制；为后续行走、换地图、冒险提供接入位置 | 后续决定将农场场景升级为复杂地图时 |

用户已选择 Phaser。使用轻量工具状态和共用图片组件，不引入状态机库。新增 FarmScene.vue 挂载 Phaser，FarmScene.ts 管理绘制和事件，farmSceneModel.ts 管理与引擎无关的布局、目标命中及占地合法性；页面继续调用现有 IPC。场景加载失败可显示错误并重试，缩放、关闭和重进页面须释放资源。场景层无存档写权限，真实状态来自 FarmView；不提前实现其他地图或寻路。

## 四、Phaser 方案的模块与状态设计

### 1. 共用物品图片

新增 `src/renderer/components/farm/FarmItemArt.vue`，统一显示作物阶段、种子与对应作物、装饰。作物从已有横向四阶段图按阶段裁切，装饰保持长宽比；图片不承担业务变更。

仓库三个分类、商店两类商品、买卖数量详情、图鉴、布置卡片均引用该组件。图鉴明确展示四个阶段，不把整张精灵图压缩成单个图标。锁定或未收获状态使用图片样式和文字说明组合。工具跟随图样复用正式素材清单。

### 2. 统一工具状态

工具状态在 `Farm.vue` 内集中维护。用互斥状态表达当前工具，不继续通过多个独立布尔变量组合状态。页面负责装备、退出和业务提交；Phaser 场景负责指针和悬停预览，纯布局模块负责命中与占地。最终资格、库存和保存由主进程处理。

播种、浇水移除操作说明条，保留鼠标图样与水壶按钮高亮；教学时长和额度放在仓库、种子抽屉卡片。装饰说明仍作为 `.field` 内绝对定位的小型悬浮条。移除全部浇水和批量播种按钮及对应页面分支，保留服务端协议和一键收获。真实 Electron 比较装备前后、切换和取消后的场景、画布、12 个地块中心及工具栏边界。

`.body` 作为场景的相对定位容器，取消常驻侧栏的网格列；`.sidebar` 改为右侧绝对定位抽屉，默认不挂载，打开时仅播放平移动画。新增 `drawerOpen`，查看地块与订单入口展开，关闭按钮、Esc、空白场景和装备工具/打开其他面板收起。工具点击目标只更新选中地块，不打开抽屉。顶部结果提示使用固定定位、无指针拦截；所有反馈统一调用 2 秒定时函数，后续反馈清除旧计时并重新开始，卸载时清理。

| 状态 | 所需信息 | 点击场景目标 |
| --- | --- | --- |
| 查看 | 无 | 地块详情，或进入既有装饰移动 |
| 播种 | 作物 ID | 合格空地提交单块播种，否则反馈原因 |
| 浇水 | 无 | 合格地块提交单块浇水，否则反馈原因 |
| 摆放 | 装饰 ID | 合法装饰格提交摆放，其他场景位置取消 |
| 移动 | 实例 ID、装饰 ID | 合法格提交移动，其他位置取消并保留旧位置 |

库存数量、教学时长、等级和目标资格从最新 `FarmView` 推导，不复制成可独立过期的库存。悬停图样属于预览，真实作物与装饰只从成功状态渲染。

Phaser 根据画布尺寸使用场景逻辑坐标，指针使用场景边界计算坐标，窗口缩放后重新取当前边界；工具层不接收事件。离开场景只隐藏图样。Esc、场景空白右键、其他功能入口与页面卸载清理工具状态。提交期间阻止再次变更；退出预览不能撤销已经提交的操作。

### 3. 目标选择与提交

移除鼠标单块播种的自动找空地回退。仓库和种子抽屉点击播种只装备并关闭面板；随后由地块点击明确传入一个地块 ID。浇水采用相同目标路径。页面移除批量种水入口，预览接口继续用于单块照料与一键收获，不允许无选中地块时单块操作自动回退到全部。

沿用 `run` 的请求编号、修订号、忙碌保护及保存结果处理。失效库存、存档故障与跨窗口刷新重新验证当前工具；恢复后清理旧预览。请求失败保留可重试的有效工具，资源及场景仍以服务返回的状态为准。

### 4. 装饰事件与占地

选择可用图片卡片立即进入预览。前端按现有左右区 2×4、底部区 8×1 共 24 格展示占地，长椅和花箱预览横向两格；移动时校验忽略该实例自身的旧占地。前端预览与主进程既有规则保持一致，主进程仍作最终校验。

删除布置流程中的“选择位置”和“确认摆放”。合法格点击调用已有 `place` 或 `move`，成功后退出；失败不新增实例、不丢失原位置。点击其他场景位置按规格取消。

已摆放实例独立处理左键移动、右键 `reclaim`；右键阻止默认菜单与冒泡，避免同时触发场景取消或摆放。收回不修改拥有总量。忙碌期间重复右键不提交第二次请求。
